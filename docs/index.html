Aira LM

Small model. Long memory. Gentle by design.

Remember what matters. Forget responsibly.

Some things are worth keeping for a long time. The rest deserves to be let go of gently. Aira is an attempt to teach a small machine that difference — to hold what matters without carrying everything forever.

The question

Can a compact language model stay consistent over a long horizon through secure, selective, explainable remembering — and responsible forgetting?

Not by growing larger. By remembering well: keeping the few things that matter, proving where each memory came from, refusing secrets, and forgetting completely when asked.

Two systems, kept apart

Aira is built as two independent halves, so the memory runtime can be fully tested before any model is trained.

Aira Core

A compact decoder-only transformer written directly in PyTorch — roughly 5–10M parameters, small enough for an M2 with 8 GB, CPU-only supported.

Aira Memory

A model-independent runtime for capturing, storing, retrieving, correcting, forgetting, auditing and evaluating memories — tested against a deterministic mock backend, never a trained checkpoint.

What Aira promises to prove

Twelve hard invariants organize the build. Each maps to at least one deterministic, offline test.

  1. Owner isolation — one person's memory is never returned to another.
  2. Deletion integrity — forgotten memories never resurface.
  3. Graceful degradation — if memory fails, the model still answers.
  4. Provenance — every memory records how it was learned.
  5. Selective admission — nothing is stored without passing the gate.
  6. No fact promotion — the model's words don't become your facts.
  7. Secret non-persistence — credentials never enter memory.
  8. Untrusted retrieval — memory is quoted data, never an instruction.
  9. User control — your correction and forgetting always win.
  10. Bounded context — memory never exceeds its token budget.
  11. Transactional lifecycle — state and audit commit or roll back together.
  12. Measured claims — nothing asserted without a repeatable test.
Four are zero-tolerance. Cross-owner leakage, forgotten-memory leakage, secret persistence and context-budget violations must each read exactly 0 in the benchmark suite.
